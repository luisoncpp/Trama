# Global markdown search scans on demand, without an index

Global search runs a full scan of the managed markdown files in the main process (`project-search-service.ts`) on every explicit search click, instead of maintaining a persistent search index or database. Project corpora stay small (~500k words), and the sidebar panel triggers searches by button rather than live-updating, so a fresh scan keeps results always consistent with disk and adds no index-invalidation surface. Matching itself (case sensitivity, Unicode-aware whole-word boundaries) is a shared pure module (`src/shared/text-search/`) used by both the main-process scan and the renderer's in-editor find bar, so the counts a search reports match what the find bar highlights after a result opens. Results hand off to the editor through the `global-search` facade's single-slot find-request mailbox — opening a result posts the searched term, `selectFile` performs the **Pane exit**-guarded navigation, and the editor session's find controller consumes the request for its document and refreshes matches when content mutation notifies it, avoiding any coupling between the sidebar panel and editor internals.
